# Korokae v2 and Vocal-Reduction Strength Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a user-adjustable vocal-reduction strength, then train, gate and ship a stereo-aware Korokae v2 (Standard on the phone, High as ONNX for the laptop) only if it beats v1 on every metric.

**Architecture:** The slider reuses `KorokaeEngine.setMix`. v2 is a new PyTorch model (`model2.py`) with its own training, loss, augmentation, evaluation and export, leaving the v1 files untouched. The Java engine learns a second weight format (KRK2) and keeps KRK1 as the fallback.

**Tech Stack:** Java (Media3, JUnit), Python 3, PyTorch, numpy, ffmpeg, pytest, onnxruntime.

**Spec:** `docs/superpowers/specs/2026-11-03-cross-platform-sync-and-korokae-v2-design.md` (sections 5.1–5.6)

## Global Constraints

- Android code is Java only, no Kotlin; minSdk 24.
- Commit messages follow Conventional Commits (`feat(korokae): ...`).
- Unit tests: `./gradlew testDebugUnitTest` must stay green at every commit.
- v1 (`korokae_v1.bin`, KRK1) stays bundled as the fallback.
- New weight format is `KRK2` with a version header and a layer config.
- Standard = phone model, similar compute budget to v1. High = bigger GRU with 2 frames of lookahead (about 23 ms extra delay at a 512-sample hop), laptop only.
- v1 baseline: 8.95 dB median accompaniment SDR, 4.50 dB mixture baseline, 4.2 MB.
- Ship gate: Standard at least +1.5 dB SDR over v1 and better vocal attenuation, within v1's real-time budget. High beats Standard on both. A model ships only if it beats v1 on every metric; otherwise v1 stays the default.
- Weights trained on MUSDB18 stay non-commercial. Any extra dataset needs a licence check against `MODEL_LICENSE.md`.
- Strength slider: 0 to 100 percent, default 100, no added latency.

## Review Focus

1. Strength value NaN, negative or above 1: clamp to 0..1 (Task 1).
2. Mono input (L equals R, side channel all zeros): output finite and correct (Task 7).
3. Digital silence: output finite and silent, no NaN from log or divide (Task 7).
4. Strength changed during playback: no click or sample jump (Task 1).
5. v2 asset missing or corrupt: fall back to v1, and to passthrough if both fail (Task 7).

### Task 7: KRK2 export and Java engine

**Files:**
- Create: `ml/korokae/export2.py`, `ml/korokae/export_onnx.py`, `ml/korokae/tests/test_export_onnx.py`, `app/src/main/assets/models/korokae_v2_standard.bin`, `app/src/test/resources/korokae2_parity.bin`, `app/src/test/java/com/psthetech/swara/Korokae2EngineTest.java`
- Modify: `KorokaeModel.java`, `KorokaeEngine.java`, `KorokaeModelProvider.java`

**Interfaces:**
- Produces (format): KRK2 header is magic `KRK2`, then little-endian int32 `version=2, nFft, hop, hidden, layers, inChannels=2, outChannels=2, lookahead`. Weights follow in this order: `mean[2*bins]`, `std[2*bins]`, `inW[hidden*2*bins]`, `inB[hidden]`, per layer `wIh, wHh, bIh, bHh` (as KRK1), `outW[2*bins*hidden]`, `outB[2*bins]`. The Java loader accepts only `lookahead == 0`.
- Produces (Java): `KorokaeModel.load(InputStream)` accepts KRK1 and KRK2; `KorokaeModel.ASSET_PATH_V2 = "models/korokae_v2_standard.bin"`; `KorokaeModelProvider.getActiveVersion() -> int` (1 or 2); the provider takes an `AssetOpener` seam, `interface AssetOpener { InputStream open(String path) throws IOException; }`, so loading can be tested without a `Context`.
- Produces (ONNX): `export_onnx.py` writes `ml/korokae/export/korokae_v2_{standard,high}.onnx` (git-ignored; desktop picks them up as release artifacts). Step signature: inputs `frames [1, lookahead+1, 2, BINS]` and `h [layers, 1, hidden]`, outputs `masks [1, 2, BINS]` and `h_next`.

- [ ] **Step 1: Write the failing tests.** Python `test_export_onnx.py`: `test_onnx_step_loop_matches_pytorch` runs a 50-frame random feature sequence through the ONNX step loop with onnxruntime and through `KorokaeNet2` in one pass for both configs; max absolute difference under 1e-4. Java `Korokae2EngineTest`:
  - `parityWithPyTorchFixture`: same tolerance and method as `KorokaeEngineParityTest`, using `korokae2_parity.bin`.
  - `monoInputProducesFiniteOutput`: L equals R for 1 s; no NaN or Infinity in the output.
  - `digitalSilenceProducesSilentFiniteOutput`: 1 s of zeros gives all finite samples with absolute value under 1e-4.
  - `krk1StillLoads`: the v1 asset loads and `getActiveVersion` logic reports 1.
  - `krk2WithLookaheadIsRejected`: a synthetic KRK2 header with `lookahead=2` throws `IOException`.
  - `providerFallsBackToV1WhenV2Corrupt`: an `AssetOpener` returning garbage for the v2 path yields version 1.
  - `providerPassesThroughWhenBothMissing`: both paths throw; `getIfLoaded()` is null and `getError()` is non-null.
  - `v2NoSlowerThan1_5xV1`: processing 10 s of audio with v2 takes at most 1.5 times the time of v1 on the same JVM.

- [ ] **Step 2: Run to verify failure**

Run: `cd ml/korokae && python3 -m pytest tests/test_export_onnx.py -v` and `./gradlew testDebugUnitTest --tests '*Korokae2EngineTest'`
